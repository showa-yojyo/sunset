* [Creating projects](https://docs.astral.sh/uv/concepts/projects/init/): ``uv
  init`` 用例詳細
  * ``--app`` vs ``--lib``
  * `pyproject.toml` `[project.scripts]` 区画
  * `--no-package` は私が使えそう
  * `--bare`
* [Managing dependencies
  ](https://docs.astral.sh/uv/concepts/projects/dependencies/): 区画が四つある。
  * `[project.optional-dependencies]` の説明を pandas を例にして述べている。
  * `[dependency-groups]` は `uv add --dev` などに対応。
    * この区画に mypy, pytest, ruff などの「開発工具」を列挙する。
    * この区画をさらに分割することが可能 (`uv add --group grp0 grp1 ...`) だ。た
      だし、あるグループで宣言された依存関係が、別のグループの依存関係と互換性が
      ないという状態は許されない。
    * 入れ子機能アリ。
* [Running commands](https://docs.astral.sh/uv/concepts/projects/run/)
  * プロジェクト内の何かを実行するときには必ず `uv run` を使え。
    * `uv run python -c "import example"`
    * `uv run bash scripts/foo.sh`
  * 単品スクリプトの状況と同様、オプション `--with` はここでも効力がある。
* [Locking and syncing](https://docs.astral.sh/uv/concepts/projects/sync/): 依存
  関係を刷新したい場合は `uv.lock` を明示的に更新する必要がある。
  * `project.optional-dependencies` と `--extra` は対応している。
  * `[dependency-groups]` の `dev` は特別扱い。
  * `uv lock --upgrade-package <package>` 必修
* [Configuring projects](https://docs.astral.sh/uv/concepts/projects/config/)
  * `tool.uv.package = false` するべきプロジェクトを持っている。
  * 編集可能モードとしてプロジェクトがインストールされるのが通常動作。
* [Using workspaces](https://docs.astral.sh/uv/concepts/projects/workspaces/):
  大規模コードベースを共通の依存関係を持つ複数パッケージに分割する整理法。ここは
  後回しでいい。

[uv]: <https://docs.astral.sh/uv/>
