Git 操作をするシェルスクリプトを書くときは自動実行を想定するほうがいい。

* SSH を使う Git 命令は `clone`, `fetch`, `pull`, `push`, `remote` らしい。
* スクリプト内でもファイルパスはフルパスで記述する
  * 環境変数 `PATH` を上書きするのはおそらく筋悪
* 環境変数 `GIT_SSH_COMMAND` を使わない手はない
  * crontab(5) とスクリプトのどちらにも記述可能。後者が望ましいとされている。
* ログファイルを作る気があるならば `--verbose` を、なければ `--quiet` を使え。

Windows Task Scheduler ではなく Ubuntu の cron(8) に `git fetch` を実行するスク
リプトの実行を仕込む。非 root 者の `crontab -e` は `$HOME` を前提としているから
パス周りの記述を自然に減らせる。

```raw
# Demonstrate SSH operations
* * * * * .local/bin/demo-git-fetch.sh /path/to/repo >>/tmp/demo-git-fetch.log 2>&1
```

* テスト後は米印を適当な日付時刻に変えておくか、使わぬならコメントアウト。
* Git を主に扱うスクリプトでは、実行者が root でないことを確認すると良さそうだ。

自動実行用のスクリプトをもう一つ作成したい。Bash で十分：

1. 必要なファイル（引数とする）に対して Copyright の年を今年の値に置換する
2. その変更を `git add` する

と悟る。やりたいことの全部を単一のスクリプトに詰め込める。[VS Code] の AI にはコ
